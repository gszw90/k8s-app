## 💡 优化实施方案

### 方案1：增强现有Runner权限（推荐）

**步骤1：创建高权限ServiceAccount**
```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: github-runner-admin
  namespace: github-runners
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: github-runner-admin-binding
subjects:
- kind: ServiceAccount
  name: github-runner-admin
  namespace: github-runners
roleRef:
  kind: ClusterRole
  name: cluster-admin
```

**步骤2：修改Runner Deployment**
```yaml
spec:
  serviceAccountName: github-runner-admin  # 使用高权限SA
  template:
    spec:
      containers:
      - name: runner
        env:
        - name: KUBERNETES_IN_CLUSTER
          value: "true"
        # 安装kubectl工具
        command: ["/bin/sh", "-c"]
        args:
        - |
          apt-get update && apt-get install -y curl gnupg
          curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
          install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl
          # 设置in-cluster配置
          cat > ~/.kube/config << 'EOF'
apiVersion: v1
clusters:
- cluster:
    certificate-authority: /run/secrets/kubernetes.io/serviceaccount/ca.crt
    server: https://kubernetes.default.svc
  name: in-cluster
contexts:
- context:
    cluster: in-cluster
    user: in-cluster-user
  name: in-cluster
current-context: in-cluster
kind: Config
preferences: {}
users:
- name: in-cluster-user
  user:
    tokenFile: /run/secrets/kubernetes.io/serviceaccount/token
EOF
          ./entrypoint.sh
```

### 方案3：直接API调用（无kubectl）

**绕过kubectl，直接使用curl调用Kubernetes API**：
```yaml
- name: 直接API部署
  run: |
    TOKEN=$(cat /run/secrets/kubernetes.io/serviceaccount/token)
    NAMESPACE="app-develop"

    # 创建Deployment
    curl -k -X POST \
      -H "Authorization: Bearer $TOKEN" \
      -H "Content-Type: application/json" \
      -d @deployment.json \
      https://kubernetes.default.svc/apis/apps/v1/namespaces/${NAMESPACE}/deployments
```
