# GitHub Runner Kubernetes部署问题分析与解决方案

## 🔍 问题确认

**根本原因**：GitHub Runner Pod无法访问Kubernetes集群API

### 验证过程
1. ✅ **Runner Pod正常运行**：`github-runner-simple-8648c8668b-7n8hs` 运行正常
2. ❌ **kubectl工具缺失**：Pod内部没有kubectl工具
3. ❌ **KUBECONFIG缺失**：Pod内部无法访问宿主机kubeconfig
4. ❌ **权限不足**：Pod默认权限无法操作集群资源

### 问题表现
- GitHub Actions的`parse-branch`和`build`任务成功 ✅
- `deploy`任务失败 ❌ - 无法执行kubectl命令
- 错误：`Job deploy completed with result: Failed`

## 💡 解决方案

### 方案1：增强Runner权限（推荐）

**优势**：直接、高效、充分利用K8s原生能力
**实施步骤**：

1. **创建高权限ServiceAccount**
```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: github-runner-admin
  namespace: github-runners
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: github-runner-admin
subjects:
- kind: ServiceAccount
  name: github-runner-admin
  namespace: github-runners
roleRef:
  kind: ClusterRole
  name: cluster-admin
```

2. **挂载kubeconfig文件**
```yaml
spec:
  serviceAccountName: github-runner-admin
  volumes:
  - name: kubeconfig
    hostPath:
      path: /home/zeng/.kube/config
      type: File
  containers:
  - name: runner
    volumeMounts:
    - name: kubeconfig
      mountPath: /home/runner/.kube/config
      subPath: config
      readOnly: true
```

3. **安装kubectl工具**
```yaml
# 在Pod启动时安装kubectl
command: ["/bin/sh", "-c"]
args:
- |
  apt-get update && apt-get install -y curl
  curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
  install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl
  ./run.sh
```

### 方案2：使用in-cluster配置

**优势**：更安全，无需挂载宿主文件
**实施**：利用Pod内置的ServiceAccount和Kubernetes API

```bash
# 在Pod内部直接使用in-cluster配置
export KUBECONFIG=/run/secrets/kubernetes.io/serviceaccount/token
kubectl --token=$(cat /run/secrets/kubernetes.io/serviceaccount/token) \
       --server=https://kubernetes.default.svc \
       --certificate-authority=/run/secrets/kubernetes.io/serviceaccount/ca.crt \
       get pods
```

### 方案3：Docker-in-Docker + K8s访问

**优势**：完整隔离，安全性高
**缺点**：复杂度高，资源消耗大

## 🚀 推荐实施方案

### 立即修复（快速方案）

1. **修改现有Runner配置**
```bash
# 停止现有Runner
kubectl scale deployment github-runner-simple -n github-runners --replicas=0

# 应用新配置（包含kubectl和kubeconfig挂载）
kubectl apply -f - <<EOF
apiVersion: apps/v1
kind: Deployment
metadata:
  name: github-runner-simple
  namespace: github-runners
spec:
  replicas: 1
  selector:
    matchLabels:
      app: github-runner-simple
  template:
    metadata:
      labels:
        app: github-runner-simple
    spec:
      serviceAccountName: github-runner-admin
      volumes:
      - name: kubeconfig
        hostPath:
          path: /home/zeng/.kube/config
          type: File
      - name: docker-socket
        hostPath:
          path: /var/run/docker.sock
          type: Socket
      containers:
      - name: runner
        image: myoung34/github-runner:latest
        env:
        - name: REPO_URL
          value: https://github.com/gszw90/k8s-app
        - name: RUNNER_NAME
          value: github-runner-simple
        - name: RUNNER_TOKEN
          valueFrom:
            secretKeyRef:
              name: github-runner-secret
              key: RUNNER_TOKEN
        volumeMounts:
        - name: kubeconfig
          mountPath: /home/runner/.kube/config
          subPath: config
          readOnly: true
        - name: docker-socket
          mountPath: /var/run/docker.sock
        command: ["/bin/sh", "-c"]
        args:
        - |
          apt-get update && apt-get install -y curl gnupg
          curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
          install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl
          kubectl config use-context docker-desktop
          ./entrypoint.sh
EOF
```

2. **创建权限配置**
```bash
kubectl apply -f - <<EOF
apiVersion: v1
kind: ServiceAccount
metadata:
  name: github-runner-admin
  namespace: github-runners
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: github-runner-admin-crb
subjects:
- kind: ServiceAccount
  name: github-runner-admin
  namespace: github-runners
roleRef:
  kind: ClusterRole
  name: cluster-admin
EOF
```
